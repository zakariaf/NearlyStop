## Store locales are not app locales, and the difference is not ours to hide

The **app** speaks English, German, Persian and Kurdish Sorani. What the
**stores** will accept as a listing localization is a shorter list and it
changes:

- Google Play supports German and Persian listing localizations. **Kurdish
  Sorani is very likely unavailable.**
- App Store Connect's list is shorter still; **Persian may not be available at
  all**, and Sorani almost certainly is not.

Verify against the current supported-localization lists **at submission time**,
not from this file — the lists move.

Where a locale is unavailable, ship the **English** listing into that market
and say in the description that the app itself speaks all four. A missing store
locale must never be allowed to reduce what the app supports, and it must never
be quietly presented as if the app were English-only.

## Screenshot framing — open

The generated shots render each screen on its own, so they carry no tab bar and
the shorter screens have empty space below the content. That is accurate but it
is not the best listing framing.

**Deliberately not fixed yet**, because the bundle identifier is changing and
the listing will be re-made against the new one anyway
(`docs/release/RELEASING.md`). When it is: pump the screens inside the app
shell so the tab bar is in frame, and add a caption band. Captions must hold
the same line the listing does — see `test/policy/listing_copy_test.dart`.

## Feature graphic — missing

Play requires a **1024×500** feature graphic. It is not generated here: it is a
piece of marketing artwork rather than a screenshot of the app, and inventing
one from the icon would be worse than leaving the gap visible. Tracked in
`docs/release/v1.0.0-gate.md`.
