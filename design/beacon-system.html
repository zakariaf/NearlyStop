Beacon NearlyStop design system

01 — The idea

Beacon

Beacon says one thing and says it loudly: you've got this, and here is exactly what to do next. It is printed rather than glassy — every card, button and input is a chunky rounded block with a 2.5px ink border and a hard, unblurred offset shadow that presses down to 2px when you touch it, so the whole interface feels physical and certain rather than soft and uncertain. Colour is bright and confident on a warm off-white: electric blue leads, sunshine yellow carries the action, coral flags anything that needs attention. Nothing is ever communicated by colour alone — every state also carries a bordered sticker badge with its own icon and word, which is why Beacon survives poor eyesight, colour-blindness, sunlight and a two-year taper.

Colour

Every colour is a CSS custom property on :root. The dark theme redefines the same names and nothing else — no component ever hard-codes a hex. Dark surfaces are warmed toward brown-charcoal (#181519, not #000000) so the dark theme stays alive rather than becoming a cold void.

06

Shadows / elevation

Beacon's most recognisable trait: hard offset shadows with zero blur, drawn in the ink colour, so a card looks printed and stacked rather than floating. Pressing a control drops it onto its shadow. In RTL the offset mirrors, driven by the --sx multiplier.

Level 1 — rows, chips, badges
--sh-1box-shadow:
calc(2px*var(--sx)) 2px 0 var(--border)
Level 2 — cards, buttons
--sh-2box-shadow:
calc(4px*var(--sx)) 4px 0 var(--border)
Level 3 — dose hero, sheets
--sh-3box-shadow:
calc(6px*var(--sx)) 6px 0 var(--border)
Pressed — flattens and moves onto the shadow
--sh-pressbox-shadow:
calc(2px*var(--sx)) 2px 0 var(--border);
transform:translate(calc(2px*var(--sx)),2px)

Never add blur, never add opacity, never use a coloured shadow. The shadow is always var(--border), which flips to the light ink in dark mode — the dark theme's cards look screen-printed too.

09

Motion

Motion in Beacon is short and mechanical — a block presses down, a switch slides, a sheet rises. Nothing bounces, nothing fades in slowly, nothing moves while the user is reading a dose.

--dur-fast · 120mspress states, badge swap
--ease cubic-bezier(.2,.8,.3,1)
--dur · 200msswitch travel, tab change
--ease cubic-bezier(.2,.8,.3,1)
--dur-slow · 320mssheet rise, banner enter
--ease-out cubic-bezier(0,.7,.3,1)

prefers-reduced-motion: reduce collapses every duration to 1ms globally. State still changes instantly and correctly — because state is carried by border, icon and word, not by the animation.

10

RTL rules

Mirrors

  • Layout order — driven by margin-inline, padding-inline, inset-inline, text-align:start
  • The hard shadow offset, via --sx: 1 → -1
  • The today row's 7px accent rule (border-inline-start)
  • Chevrons, back arrows, the switch knob's travel
  • Slider fill direction and the progress staircase

Does not mirror

  • Clock, pill, tick, spark, flame, gear, shield, chart
  • The status bar battery and signal glyphs
  • Latin brand name 'NearlyStop' inside Persian copy

Numerals and dates

Persian uses Persian-Indic digits ۰۱۲۳۴۵۶۷۸۹ with the Arabic thousands separator ٬ and decimal ٫ (6,842 → ۶٬۸۴۲ · 0.9 → ۰٫۹). Dates use the Persian calendar: Wednesday 16 April 2026 → چهارشنبه ۲۷ فروردین ۱۴۰۵.

Text scaling

Every component is built in em and relative units inside a root px scale, so the OS text-size setting scales the whole interface. Rows wrap rather than truncate, buttons grow in height rather than clipping their label, and no layout depends on a fixed line count. Below: the same card at 100%, 150% and 200%.

Rules that are not negotiable

  • Body text never below 17px; --ink-muted is only used at 15px or above and only for text that repeats information available elsewhere.
  • Every state carries a border, an icon and a word. Colour is the third signal, never the first.
  • Focus is a 3px coral ring at 3px offset — visible against every surface in both themes.
  • Every interactive element has an accessible name; icon-only controls carry aria-label.
  • The 2.5px border means every card, button and input meets the 3:1 non-text contrast requirement on its own, without relying on a fill.
  • No horizontal page scroll at any width — wide content (tables, the staircase chart) scrolls inside its own container.
